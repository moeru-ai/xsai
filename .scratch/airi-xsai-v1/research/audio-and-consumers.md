# Audio and consumer migration research

## Scope and source state

This note compares xsAI `3cabb2b0` (`1.0.0-beta.3`) with AIRI `3b0672e36` (`0.12.0`). The inventory covers tracked source and manifests. It excludes dependency installations and generated files.


Both repositories target Node 26. xsAI packages declare Node `>=26` ([packages/audio/package.json:32-34](../../../packages/audio/package.json#L32-L34), [packages/embed/package.json:29-31](../../../packages/embed/package.json#L29-L31), [packages/model/package.json:29-31](../../../packages/model/package.json#L29-L31)). AIRI pins Node `26.7.0` ([.tool-versions:1](https://github.com/moeru-ai/airi/blob/3b0672e3668bd1ade1210e579818f379e4f8a224/.tool-versions#L1)), so the engine range is not a migration blocker.

## xsAI beta.3 contracts

`@xsai/audio` owns speech and transcription ([packages/audio/package.json:2-5](../../../packages/audio/package.json#L2-L5)). It exposes a function model. `SpeechModel` receives `{ input, voice, signal, providerOptions }` and returns a `Response` ([packages/audio/src/speech/model.ts:1-10](../../../packages/audio/src/speech/model.ts#L1-L10)). `speech(httpOptions)` creates an OpenAI compatible `/audio/speech` model and `streamSpeech` returns the response. `generateSpeech` collects the response into a `Blob` ([packages/audio/src/speech/model-speech.ts:25-53](../../../packages/audio/src/speech/model-speech.ts#L25-L53), [packages/audio/src/speech/generate.ts:1-6](../../../packages/audio/src/speech/generate.ts#L1-L6)).

`TranscriptionModel` receives `{ audio, fileName, language, signal, providerOptions }` and returns a stream of normalized `TranscriptionEvent` values ([packages/audio/src/transcription/model.ts:1-15](../../../packages/audio/src/transcription/model.ts#L1-L15)). The JSON and SSE adapters use `/audio/transcriptions` ([packages/audio/src/transcription/model-transcriptions.ts:179-205](../../../packages/audio/src/transcription/model-transcriptions.ts#L179-L205)). The result uses camel case segment fields and puts provider details under `providerMetadata.transcriptions`, for example `avgLogprob` ([packages/audio/src/transcription/event.ts:11-50](../../../packages/audio/src/transcription/event.ts#L11-L50), [packages/audio/test/transcription.test.ts:10-45](../../../packages/audio/test/transcription.test.ts#L10-L45)). `generateTranscription` requires one final `transcription.end` event ([packages/audio/src/transcription/generate.ts:5-18](../../../packages/audio/src/transcription/generate.ts#L5-L18)). The core adapter accepts a `Blob`. It does not accept AIRI's live `ReadableStream` input.

`@xsai/embed` separates model construction from consumption. `embeddings(httpOptions)` creates an `EmbeddingModel`. `embed(model, { input, signal, providerOptions })` returns the first vector and usage ([packages/embed/src/model.ts:1-21](../../../packages/embed/src/model.ts#L1-L21), [packages/embed/src/model-embeddings.ts:15-39](../../../packages/embed/src/model-embeddings.ts#L15-L39), [packages/embed/src/embed.ts:5-14](../../../packages/embed/src/embed.ts#L5-L14)).

`@xsai/model` separates a model catalog from its HTTP adapter. `ModelCatalog` has `list` and `retrieve`. `models(httpOptions)` creates the catalog and `listModels(catalog)` lists entries ([packages/model/src/model.ts:3-20](../../../packages/model/src/model.ts#L3-L20), [packages/model/src/model-models.ts:27-36](../../../packages/model/src/model-models.ts#L27-L36), [packages/model/src/list-models.ts:1-4](../../../packages/model/src/list-models.ts#L1-L4)).

The `xsai` package exports the new audio, embed, model, and text packages ([packages/xsai/src/index.ts:1-10](../../../packages/xsai/src/index.ts#L1-L10)). It does not export the AIRI-era packages `@xsai/generate-speech`, `@xsai/generate-transcription`, or `@xsai/stream-transcription`.

## Proposed ownership and order

Keep active providers available. Removing an active provider changes user-facing behavior and falls outside this effort.

### xsAI and related package owners

1. Lock the 1.0 names and option names for `@xsai/audio`, `@xsai/embed`, and `@xsai/model`. Keep the breaking constructor split. Do not add aliases for the removed 0.5 package entry points.
2. Keep live audio scope as an explicit decision before AIRI changes Hearing. Decide whether core xsAI adds a streaming input contract, AIRI owns the wrapper, or native providers stay AIRI-owned. The beta.3 core contract supports `Blob` input and normalized events. It does not define live input or replacement snapshots.
3. Treat upstream releases as migration options. `@xsai-apple-speech`, `@xsai-transformers`, and `@sherpaw/xsai-transcription` need compatible releases when AIRI retains their old package boundaries. AIRI can remove or replace `@xsai-ext/providers` locally. None of these releases is required work for xsAI core 1.0.
4. Keep the current normalization rules and tests. In particular, preserve speech `Response` streaming, `Blob` collection, transcription terminal events, provider metadata, embedding input order, and model catalog list and retrieve behavior ([packages/audio/test/speech.test.ts:9-53](../../../packages/audio/test/speech.test.ts#L9-L53), [packages/audio/test/transcription.test.ts:10-45](../../../packages/audio/test/transcription.test.ts#L10-L45), [packages/embed/test/model-embeddings.test.ts:5-46](../../../packages/embed/test/model-embeddings.test.ts#L5-L46), [packages/model/src/model.ts:3-20](../../../packages/model/src/model.ts#L3-L20)).

### AIRI

#### Safe preparation on 0.5.1

AIRI can complete these steps while the old xsAI packages remain installed:

1. Inventory provider IDs, configuration keys, stored settings, model defaults, voice IDs, vector dimensions, and the current speech and transcription result shapes.
2. Add internal domain types and adapter interfaces in `packages/provider-inference` for speech, file transcription, embeddings, model catalogs, and the existing live stream. Keep these interfaces independent of `@xsai/audio`, `@xsai/embed`, and `@xsai/model`.
3. Put the old calls behind the adapters. Add fixtures for provider options, cancellation, audio bytes, transcription metadata, model lists, and embedding dimensions. Keep provider IDs, configuration keys, local storage keys, and settings pages unchanged.
4. Record the mapping from old calls to the 1.0 calls. Keep the current embedding and model calls until the upgrade. Do not introduce 1.0-only calls in preparation.
5. Remove dead Transformers package declarations after a tracked-source search. Replace the `ProgressInfo` type-only imports locally or keep the shared package until cleanup. Do not re-enable the commented local embedding path.
6. Keep live native and worker paths behind the AIRI stream boundary. Record the live audio scope decision before changing Hearing. Native providers can stay AIRI-owned while the core input contract remains open.

#### Upgrade-dependent cutover

Run these steps only after the AIRI package catalog and manifests point to the selected xsAI 1.0 packages. New `@xsai/audio`, `@xsai/embed`, and `@xsai/model` calls belong to this phase.

1. Add the new package imports and construct the speech, transcription, embedding, and model catalog instances with their 1.0 APIs.
2. Migrate Stage first. Replace speech calls in the speech store and devtools. Convert the returned `Blob` to the playback input at one boundary. Replace file transcription calls with `@xsai/audio` and map `abortSignal` to `signal`, `file` to `audio`, and old flat options to `providerOptions.transcriptions`.
3. Map new transcription metadata into the Hearing domain result. The mapper must preserve confidence filtering, empty results, language, segments, cancellation, and analytics. Add tests for `avgLogprob` and missing segments.
4. Keep live native and worker paths behind the selected AIRI or xsAI stream boundary. Test partial replacement, final text, cancellation, worker disposal, and the 16 kHz PCM conversion. Do not route Apple Speech or Sherpaw through the file-only core adapter.
5. Adapt model listing through `models(httpOptions)` and `listModels(catalog)`. Preserve model IDs, default selection, provider labels, and the current settings UI.
6. Include package manifests, the lockfile, and their dependent adapters in one coherent cutover batch. Update or replace Apple Speech and Sherpaw integrations while preserving their current capabilities. Validate Stage Web, Stage Pocket, Stage Tamagotchi, and Stage Tamagotchi Kirie. Then migrate evals, Discord transcription, and Telegram embeddings. Migrate text-only bots and plugins through the text ticket.
7. Remove old package references from tracked source and manifests only after the whole monorepo passes the selected validation. Keep `unspeech`, Chrome Prompt API, Hugging Face local transcription, Kokoro model loading, Apple native packaging, Sherpaw model assets, and the database vector columns stable.

## Stage-first acceptance gates

After the 1.0 package upgrade, the Stage cutover can proceed when all of these conditions hold:

- The Stage packages build and typecheck with `@xsai/audio`, `@xsai/embed`, and `@xsai/model` 1.0 packages. No Stage source or manifest imports `@xsai/generate-speech`, `@xsai/generate-transcription`, or `@xsai/stream-transcription`.
- A mocked speech request produces the same provider selection, voice ID, SSML input, audio bytes, and cancellation behavior. The only internal change is the `Response` and `Blob` conversion.
- File transcription returns the same text and segment behavior. The confidence threshold uses the new provider metadata path. A missing `transcription.end` event still fails the request.
- Apple Speech and Sherpaw keep partial replacement, final text, abort, worker disposal, and native Electron lifecycle behavior.
- Model listing returns the same IDs and default choices. The current settings pages and configuration values remain unchanged.
- Kokoro, Prompt API, `unspeech`, and the Stage Web, Pocket, Tamagotchi, and Kirie packaging paths pass focused tests.
- After Stage passes, Telegram backfill and live embedding preserve vector dimensions and existing database rows. Discord remote transcription returns the same text. A final tracked-source search finds no old package entry points anywhere in the AIRI monorepo.
